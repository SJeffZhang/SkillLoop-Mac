## Admission rule

The formal operator service must not accept a route whose frozen public result has no lawful production issuer. Current unavailable commands are `evaluate`, `harden`, `admin review-finding`, `admin retire-history`, `admin archive`, `admin restore`, and `admin calibrate`; they fail before a campaign side effect. The two newly fenced Admin commands were previously delegated to the Proxy, whose actual ApprovalAuthority accepts only `approve_domain` and `approve_factory`. This preserves the original role boundary and prevents a started operation with no result producer. The blocked commands are not counted as implemented or accepted.

The installed `skillloop` command now requires its Admin-owned operator deployment document for every public command. Without it, `import`, `scan`, `report`, `promote`, and Admin approvals also return a stable unavailable result instead of bypassing the Controller operation store. Their underlying component functions remain available to authorized internal callers; those calls do not constitute a formal CLI campaign result.

Deployment production now requires one sealed `OperatorFrontendDeployment` document for each declared operator UID, with the same deployment epoch and actual Controller socket, Admin-owned directory custody, and a caller-readable `operator.json`. The trusted operator environment must still mount that exact directory at `/etc/skillloop` and expose the shared socket; no such current deployment artifact or live frontend has been observed.

The Controller and Proxy must be started by a trusted deployment bootstrap before the operator service accepts a request. A route running inside Controller can start only later auxiliary service roles; it cannot start another Controller or the Proxy it already depends on. `skillloop.runtime.pre_operator_bootstrap` is now the explicit Linux bootstrap caller: it reads a root-owned sealed launch record, charges the original approval/deployment slot against the complete three-profile manifest (including a genuinely fresh ledger), forks the Admin deployment producer under UID 21010, permanently drops to Controller UID 21001, provisions the retained volume and Keeper, starts the original Proxy and Controller, checks both live processes and the Controller's actual operator socket peer, then records one durable completion. The bootstrap and role deployment journals are distinct; an unknown create or start keeps its original identity. This is source wiring, not observed deployment. The actual frozen launch record, image, mounted volume, 17-route bundle and first full-round budget have not yet been supplied or run.

A cross-role source check found that the Factory's actual opaque reference is `protected-` plus 32 lowercase hex characters. The native host export previously required a SHA-256 digest at the same argument, so a genuine Factory commit could never be exported for Admin import. The export now accepts the exact Factory handle shape and still binds it to the independent Gate lookup. This repairs an impossible handoff shape; it is not runtime evidence.

`skillloop.runtime.native_round_host` is the trusted host process caller for the original dev-to-protected backend switch. It starts the approved dev backend before any frozen roster exists, reads only the original Controller container's Gate-owned roster projection and Evaluator-owned opaque Factory commit through bounded Docker archives, stops dev, starts a new protected backend, exports the original process records, stays alive until the exact protected-close route step, then closes the protected backend. Its host journal is single-use; a restart cannot silently create a second process. `native_admin_transfer` now writes the exact three exported files to one frozen Admin input volume subpath using a restricted no-network sidecar, then reads back the original bytes and ownership; a lost upload response preserves the sidecar and does not retry. The formal deployment still lacks the frozen host launch policy, a verified binding from that Admin input subpath to the later `import_lifecycle` role mount, and a whole-round charge/retirement for the transfer sidecar. Until those are produced and exercised, lifecycle and fresh-private acceptance remain unavailable.

The import role previously required a Controller-produced job with the Factory opaque reference and host export digest already filled in. Those values exist only after Factory and host export, so a static route could not supply them honestly. The Admin import now accepts a frozen static production recipe, reads the actual Evaluator public commit and the transferred original host files under their respective kernel ownership, persists one derived job, and imports that exact job. The old direct job path remains a compatibility path; formal deployment admission still needs to require the production recipe and verify its mount against the host transfer destination.
